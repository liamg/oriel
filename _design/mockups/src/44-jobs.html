When it ends
The run row gets its status and the agent's summary; blocked also lands in Requests.
What a job is
A saved prompt you press Run on. A title, the prompt, and a few pins: sandbox or host, provider, model and effort, worker.
It names no repo or branch. The prompt names the repos it needs; the agent adds them each run, against whatever they look like that day. That's what makes it reusable.
Repos the prompt names are picked out in their project colours, so you see what a run will touch before you press Run.
Runs as sessions
Each run is a session of kind job (sessions.md) and works on its own to done or blocked; you can stop it. While it runs it has a session tab like any other.
A run row has its status, repos, the agent's summary, cost and duration. Open while it's live, Resume after; Delete throws away its worktrees, never the repos.
Blocked lands in Requests too, with the agent's question.
Where it lives
Jobs are files under ~/.oriel/jobs on the worker, one JSON per job, named by a slug of the title.
Runs are workspaces, in the run root like any session's. Deleting a job keeps its runs: the work outlives the prompt.
Each run gets the prompt as JOB.md in a fresh, empty workspace. The page lists every worker's jobs, each marked with its worker.
Keys, and new versus crit
:Jobs ⌘⇧J (proposed), the sidebar's Jobs, the start view. :Run a job by name from the omnibox. In the page: j k, n new, e edit, ⌘↵ run, ⏎ opens the run.
New: a schedule (proposal; manual by default), per-repo cost on each run linking to its session stats, provider and model pins, and runs as first-class sessions.
Kept from crit: the sandbox pin, Open/Resume/Delete, titles from the prompt's first line.
