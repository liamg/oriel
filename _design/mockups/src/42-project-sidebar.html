What it gets right
Projects at a glance. Every header carries branch, ahead, changes, PR and a CI dot, so api failing CI shows while you work in admin-ui. Switching is one click or ⌃2.
The open project is never a hidden mode. It's the one expanded header, and the dock header names it: "admin-ui · Explorer".
Each project remembers its panel. Going back to api reopens its Pull request, not admin-ui's Explorer.
Degrades cleanly: one project or a directory is a labelled rail with no header; Pull request appears only with a remote.
What it costs
Horizontal space. The wide form takes ~225px beside the dock, so 465px before the editor; the narrow form gives it back at today's rail width.
Height with many projects. A folded header is two lines; past ~8 projects the list scrolls, with the session's entries pinned below.
Ship spans projects. Each project's Pull request is its own checklist; 18's merge order across PRs is a session-wide Ship entry under the divider, shown with 2+ PRs.
Narrow initials collide (admin-ui, api): two letters plus the project colour; hovering shows the header line.
Keys
⌃1–⌃9 jump to a project: it expands, the open one folds, its last panel reopens (⌥1–⌥3 stay Explorer scopes).
In the sidebar: j k move over headers and entries, ⏎ expands a header or opens an entry in the dock.
⌘⇧E ⌘⇧G ⌘⇧T open that panel for the open project; ⌘⇧R ⌘⇧F stay session-wide. Clicking the open entry hides the dock, as the rail does today.
« / » at the top toggles wide and narrow, remembered per window.
